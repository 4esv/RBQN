## External Build-Time Dependency: CBQN

**Critical integration.** The build script (`crates/rbqn/build.rs`) depends on pre-compiled bytecode from the CBQN reference implementation.

**CBQN Source:**
- Repository: [https://github.com/dzaima/CBQN](https://github.com/dzaima/CBQN)
- Required files: `build/{bytecodeLocal,bytecodeSubmodule,obj/*}/gen/{runtime0,runtime1,compiles,formatter}`
- These are C source files generated by CBQN's build process that contain the self-hosted BQN runtime and compiler as bytecode

**Setup:**
```bash
# Clone and build CBQN to generate bytecode
git clone https://github.com/dzaima/CBQN /path/to/CBQN
cd /path/to/CBQN
make bytecodeLocal

# Then build RBQN pointing to it
CBQN_PATH=/path/to/CBQN cargo build
```

**Discovery logic** (in `crates/rbqn/build.rs`):
1. Check `$CBQN_PATH` env var
2. Check `../cbqn-ref`, `../cbqn` relative to `crates/rbqn/`
3. Check `../../cbqn-ref`, `../../cbqn` relative to `crates/rbqn/`
4. Validate by checking for `src/load.c` in the candidate directory

**What gets extracted:**
- Integer arrays (`iarrs_data[]`, `iarrs_lens[]`)
- Object entries (provide references, floats, chars, strings, runtime references)
- Block metadata (type, immediacy, body indices)
- Body definitions (bytecode offsets, variable counts)

## GPU Compute (wgpu)

**Integration:** `crates/rbqn-gpu/` uses wgpu for GPU-accelerated array operations.

**SDK/Client:** `wgpu` 24.0.5
- Context creation: `crates/rbqn-gpu/src/context.rs`
- Buffer management: `crates/rbqn-gpu/src/buffer.rs`
- Compute pipeline: `crates/rbqn-gpu/src/pipeline.rs`
- Operation dispatch: `crates/rbqn-gpu/src/dispatch.rs`
- Kernel fusion: `crates/rbqn-gpu/src/fusion.rs`

**Backend selection** (`crates/rbqn-gpu/src/context.rs`):
- macOS: Metal backend (`wgpu::Backends::METAL`)
- Other platforms: All available backends (`wgpu::Backends::all()`)

**Shaders** (`crates/rbqn-gpu/src/shaders/`):
- `arith_f32.wgsl`, `arith_i32.wgsl` - Element-wise arithmetic (add, sub, mul, div)
- `arith_scalar_f32.wgsl`, `arith_scalar_i32.wgsl` - Scalar-array arithmetic
- `reduce_f32.wgsl`, `reduce_i32.wgsl` - Reduction operations
- `scan_f32.wgsl`, `scan_i32.wgsl` - Scan/prefix-sum operations
- `select_f32.wgsl`, `select_i32.wgsl`, `select_u32.wgsl` - Selection/indexing
- `sort.wgsl` - Sorting

**Async bridge:** `pollster` 0.4.0 blocks on wgpu async device creation

**No auth or env vars required.** GPU availability is detected at runtime; operations fall back to CPU if unavailable.

## Bootstrap Chain

The most important "integration" is the 4-stage bootstrap process that converts CBQN bytecode into a working BQN runtime. Implemented in `crates/rbqn/src/bootstrap.rs`:

1. **Stage 0 (Native):** 64 primitive functions registered in `crates/rbqn-prim/src/dispatch.rs`, converted to NaN-boxed callable values
2. **Stage 1 (runtime0):** Execute embedded `RUNTIME0` bytecode with 40-element provide array, produces ~24 override functions
3. **Stage 2 (runtime1):** Execute embedded `RUNTIME1` bytecode referencing runtime0 results, produces final 64-element runtime array
4. **Stage 3 (compiler):** Execute embedded `COMPILER` bytecode, call result with glyph arrays to get the BQN compiler function
5. **Stage 4 (formatter):** Execute embedded `FORMATTER` bytecode (optional), produces format/repr functions

Each stage uses `crates/rbqn-vm/src/compiler.rs` (`compile_all`) to parse bytecode into executable blocks, then evaluates the top-level block.
