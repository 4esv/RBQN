**Cross-crate access:** `rbqn-vm` does not depend on `rbqn` or `rbqn-gpu`. Use the same function pointer pattern.

In `modifiers.rs`, add near the top:
```rust
use std::sync::OnceLock;

// NOTE: GPU fold hook — reduces large numeric arrays on GPU
// Returns Some(B) if GPU handled the fold, None for CPU fallback
type GpuFoldFn = fn(f: B, arr: &BqnArr) -> Option<B>;
static GPU_FOLD_HOOK: OnceLock<GpuFoldFn> = OnceLock::new();

pub fn register_gpu_fold(f: GpuFoldFn) {
    let _ = GPU_FOLD_HOOK.set(f);
}
```

**In `fold_c1`**, after the `n == 0` check and before `let mut acc = get_elem(&arr, n - 1)`:

```rust
// GPU dispatch for large rank-1 numeric arrays with supported ops
if arr.rank() == 1 {
    if let Some(hook) = GPU_FOLD_HOOK.get() {
        if let Some(result) = hook(f, &arr) {
            return result;
        }
    }
}
```

**In `gpu_runtime.rs`, add `gpu_fold`:**

`pub fn gpu_fold(f: B, arr: &BqnArr) -> Option<B>`:
1. Check `get()` returns Some
2. Check `should_dispatch("reduce", arr.ia())`  — reduce threshold is 50K
3. Check `gpu_safe_arr(arr)`
4. Identify the function `f`: extract prim_idx from the Derived object. Need to peek at the Derived to get the primitive index. Use `rbqn_vm::derive::get_derived(id)` where `id = (f.0 & 0xFFFFFFFFFFFF) >> 3`. Check `DerivedKind::NativeFn { prim_idx }`.
5. Map prim_idx to GPU reduce op:
   - prim_idx 6 (+) → "add"
   - prim_idx 10 (×) → "mul"
   - prim_idx 12 (⌊) → "min"
   - prim_idx 13 (⌈) → "max"
   - Other → return None (CPU fallback)
6. Upload array via `arr_to_gpu_i32`
7. Call `rbqn_gpu::kernels::reduce::reduce(device, queue, &mut cache, op, &buf)`
8. The reduce kernel returns a GpuBuffer with 1 element. Download via `pollster::block_on(download_i32(...))`.
9. Return `Some(B::m_f64(result[0] as f64))` (or `B::m_i32(result[0])`)
10. Log dispatch: `log_dispatch("reduce_add", arr.ia(), "i32")`
11. Wrap in catch_unwind for GPU error resilience — return None on panic (CPU fallback), log warning

**IMPORTANT:** The `gpu_fold` function needs access to `rbqn_vm::derive::get_derived` to inspect the function. Since `gpu_runtime.rs` is in `rbqn` crate which depends on `rbqn-vm`, this is fine. But the type signature `fn(f: B, arr: &BqnArr) -> Option<B>` means the function pointer in `modifiers.rs` (rbqn-vm) calls back into `rbqn` crate. This is exactly the function pointer pattern — no circular dep.

To get prim_idx from B: `f.is_fun()` check, then extract derived ID, call `rbqn_vm::derive::get_derived(id)`, match on `DerivedKind::NativeFn { prim_idx }`.

**In `main.rs`, register the hook:**
```rust
rbqn_vm::modifiers::register_gpu_fold(gpu_runtime::gpu_fold);
```
