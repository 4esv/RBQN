    ## Root cause (confirmed via debug instrumentation)

    When `-p '•Glyph +'` is evaluated, BQN creates the atop train `•Glyph ∘ +`. The BQN formatter displays this train by calling •Glyph on each component to get their names. The call to `dispatch_sys_glyph_c1` with the `•Glyph` SysFn (sys_idx=4) falls through to the non-primitive branch and returns `"(function block)"`. CBQN's `glyph_c1` has `pfn_repr(NID(...))` for built-in functions, returning `"•Glyph"`.

    The second issue: for `NativeFn { prim_idx }`, RBQN returns `str_to_b(glyph)` (char array), but CBQN returns `m_c32(glyph_char)` (scalar char). This means the primitive glyph is type-incompatible with CBQN's return type.

    ### Step 2: Update `dispatch_sys_glyph_c1`

    Replace the current implementation:

    ```rust
    fn dispatch_sys_glyph_c1(x: B) -> B {
        let prims = rbqn_prim::get_runtime();
        if let Some(idx) = native_prim_idx(x)
            && idx < prims.len() {
                // NOTE: Return scalar char (m_c32), not char array (str_to_b).
                // CBQN uses m_c32(glyph_char) for primitives, matching BQN type semantics.
                let glyph_char = prims[idx].glyph.chars().next().unwrap_or('+');
                return B::m_c32(glyph_char as u32);
            }
        // System functions: return the •Name string
        if x.is_fun() {
            let id = (x.0 & 0xFFFFFFFFFFFF) >> 3;
            let d = get_derived(id);
            if let DerivedKind::SysFn { sys_idx } = d.kind {
                return str_to_b(sys_fn_name(sys_idx));
            }
        }
        // Non-primitive blocks and derived values: return descriptive string matching CBQN
        let desc = if x.is_fun() {
            "(function block)"
        } else if x.is_md1() {
            "(1-modifier block)"
        } else if x.is_md2() {
            "(2-modifier block)"
        } else {
            "(derived function)"
        };
        str_to_b(desc)
    }
    ```
