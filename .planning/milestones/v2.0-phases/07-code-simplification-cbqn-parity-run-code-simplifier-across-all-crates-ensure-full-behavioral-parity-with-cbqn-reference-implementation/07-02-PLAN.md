    Investigate `format_result()` in main.rs (around line 383). The function calls `c1(fmt_fn, val)` where `fmt_fn` is `rt.formatter.0`. In CBQN, the formatter has two functions: index 0 is •Fmt (produces box-drawing display), index 1 is •Repr (produces BQN source representation).

    **Gap 3 (Error message double-prefix):**
    The error output currently shows `Error: Domain error: Assertion error: Assertion failed: 0` — the "Domain error:" prefix is duplicated because:
    1. `throw()` in error.rs panics with a `BqnError::Domain` formatted string
    2. `exec.rs` catches the panic and wraps it in another `BqnError::Domain`
    3. The Display impl prepends "Domain error:" again

    Fix: In `exec.rs` (around line 46-57), when catching a panic that already contains a BqnError message, extract the inner message without re-wrapping. Specifically:
    - If the panic payload is already a formatted BqnError string starting with "Domain error:" or similar, don't wrap it in another BqnError::Domain.
    - Alternatively, change the catch site to detect and use the inner error directly.

    Additionally, ensure the error output format is:
    ```
    Error: Assertion error
    ```
    Not:
    ```
    Error: Domain error: Assertion error: Assertion failed: 0
    ```

    NOTE: Source location tracking (showing `(-p):1:` with code context and caret) is a significant feature requiring AST span tracking — defer this to a future phase. Only fix the double-prefix issue.

    **Gap 4 (•Glyph for non-primitive functions):**
    In `derive.rs` around line 1888-1922, `dispatch_sys_glyph_c1` returns empty string for non-primitive functions. Fix to return descriptive strings matching CBQN:

    - Block 1-modifiers: `"(1-modifier block)"`
    - Block 2-modifiers: `"(2-modifier block)"`
    - Derived functions (trains, etc.): `"(derived function)"` or similar
    - For primitive functions: keep existing glyph lookup (already works)
