    Use CBQN as reference oracle: run the same expression in CBQN and RBQN, compare results.
    Use `RBQN_COMP_TRACE=1` and `RBQN_PRIM_TRACE=1` to trace VM execution when needed.

    Known failing expressions to fix (in priority order):

    1. `3×4` returns 3 instead of 12 — this is a critical arithmetic bug. Trace the compiler output
       for `3×4` using RBQN_COMP_TRACE=1. The compiler likely generates correct bytecode but the
       VM may be mishandling FN2C or the operand stack order. Compare the bytecode with what CBQN
       generates. Check if this is a regression from how the runtime array was built (fruntime vs
       rtObjRaw entries).

    2. `+´1‿2‿3` errors with "Interpreting non-1-modifier as 1-modifier" — the compiled code for
       fold (´) may be referencing a wrong runtime index. The runtime array uses fruntime (native
       primitives), so `runtime[50]` should be fold (´). Trace the compiler output to see what
       object index it uses for ´ and verify it resolves to the correct primitive.

    3. String literals fail with "!𝕩: 𝕩 must be 0 or 1" — this assertion comes from the BQN
       runtime's assert function. The compiled code for `"hello"` should just push a character
       array. Trace the compiler output to find where the assertion fires. This may be related
       to how the compiler validates string literals.

    4. `•PrimInd "+"` fails with "index out of bounds: the len is 2 but the index is 132" —
       the dispatch_sys_primind_c1 function needs to handle string arguments. Currently it
       likely receives a character array and tries to index into PRIM_GLYPHS incorrectly.
       Fix: extract the first character from the string, then search PRIM_GLYPHS for a match.

    For each bug: diagnose with tracing, identify root cause, fix, verify with the expression,
    and check that previously working expressions still work. Commit each fix individually.

    After fixing the known bugs, test these additional expressions:
    - `2⊸+¨ 1‿2‿3` (modifier with bind)
    - `{𝕩+1} 5` (block function)
    - `(1+2)×(3+4)` (parenthesized sub-expressions)
    - `↕5` (range)
    - `⌽ "abc"` (reverse string)

    If any fail, debug and fix them as well. The goal is that common BQN patterns work.
