  <name>Task 1: Build NSDesc from body_arr[2]/[3] in compile_block</name>
  <files>crates/rbqn-vm/src/compiler.rs</files>
  <action>
In compile_block's body-processing loop (after reading vam from body_arr.get(1)), add NSDesc construction when body_arr has 4+ elements (bo_ia >= 4):

1. Read `var_ids_b = body_arr.get(2)` and `export_mask_b = body_arr.get(3)`
2. If both are arrays, iterate over them to build the export GID table
3. Apply the CBQN implicit-arg offset: `off = (ty==0?0:ty==1?2:3) + (imm?0:3)` — this accounts for implicit args (𝕤/𝕩/𝕨 for functions, 𝕄/𝕩/𝕨/𝔽/𝔾/𝕣 for modifiers) that occupy the first `off` variable slots
4. For each variable slot `i` in var_ids_b where export_mask_b[i] is nonzero: look up `comp.name_list[var_ids[i]]` to get the name string, call `namespace::str2gid(&name)` to get the global ID, store it at `exp_gids[i + off]`
5. Create `NSDesc { var_am: (ia + off) as i32, exp_gids }` wrapped in `Arc`
6. Assign the NSDesc to the Body after construction

The code pattern from 04-RESEARCH.md "Parsing body namespace data in compiler.rs" section is the reference implementation — adapt it to fit the existing compile_block loop. Key detail: `vam` read from body_arr.get(1) is the count EXCLUDING implicit args. The `actual_vam` for NSDesc must include the offset.

Create a helper function `build_ns_desc(var_ids_b: B, export_mask_b: B, vam: usize, name_list: B, imm: bool, ty: u8) -> Option<Arc<NSDesc>>` to keep compile_block readable.

IMPORTANT: Only build NSDesc when export_mask has at least one nonzero entry. Don't create empty descriptors — they cause spurious RETD namespace returns for non-namespace blocks.
