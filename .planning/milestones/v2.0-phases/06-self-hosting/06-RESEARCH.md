## Summary

Phase 6 removes CBQN as a build-time dependency by precompiling all four bootstrap stages (runtime0, runtime1x, compiler, formatter) into binary files committed to the repository. The current `build.rs` is a ~380-line C-source parser that reads CBQN's gen/ directory; this logic moves entirely to a new `rbqn-gen` dev binary. The main build then uses `include_bytes!` on committed `.bin` files with no external tooling required.

The self-hosting verification (SELF-01/02) works as follows: `rbqn-gen` runs CBQN to regenerate the gen/ files, converts them to `.bin` format, and ALSO uses RBQN's own running compiler to compile the BQN sources (c.bqn, r1.bqn, f.bqn). The 13-test suite then validates that RBQN-compiled bytecode produces identical results. The initial committed `.bin` files are CBQN-generated for reliability; future runs of `rbqn-gen` can verify self-compilation parity.

The four technical sub-problems are: (1) defining a simple binary wire format for `EmbeddedBytecode`, (2) building `rbqn-gen` from the existing build.rs parser, (3) stripping build.rs down to a presence check, and (4) wiring `include_bytes!` into `embedded/mod.rs` with a decode step.

**Primary recommendation:** Use a custom tag-length-value binary format for `.bin` files. Decode at startup in `bootstrap.rs` (once, ~1ms overhead). No external serialization crates needed.

### Pattern 1: include_bytes! with startup decode

**What:** The `.bin` files are embedded as `&'static [u8]` at compile time. At startup, `decode_bytecode(bytes) -> OwnedBytecode` decodes the binary data into a usable struct.

**When to use:** Always — this is the only path after Phase 6.

**Example:**


### Pattern 2: Binary wire format for .bin files

**What:** A simple tag-length-value format with a magic header. No alignment requirements. Little-endian throughout.

**When to use:** Written by `rbqn-gen`, read by `decode_bytecode`.

```
[magic: 4 bytes = b"RBQN"]
[version: u32 LE = 1]
[bc_len: u32 LE]
[bc data: i32×bc_len LE]
[iarrs_count: u32 LE]
  for each iarr:
    [len: u32 LE]
    [data: i32×len LE]
[objs_count: u32 LE]
  for each obj:
    [tag: u8]  -- 0=Provide, 1=Runtime, 2=RuntimePrev, 3=Float, 4=Char, 5=Str, 6=IArr
    [payload: tag-specific bytes]
      Provide/Runtime/RuntimePrev/IArr: u32 LE (the index)
      Float: f64 LE (8 bytes)
      Char: u32 LE (Unicode codepoint)
      Str: u32 LE (len), then u32×len LE (codepoints)
[blocks_count: u32 LE]
  for each block:
    [tag: u8]  -- 0=IArr(n), 1=Info{typ, iarrs0_idx, data_idx}
    [payload: IArr→u32 LE; Info→u8+u32+u32]
[bodies_count: u32 LE]
[bodies data: u32×bodies_count LE]
```

Total size estimate: runtime0 gen file is 5KB text → binary is ~2KB. Compiler gen is 47KB text → binary ~15KB. All four files combined: ~25KB binary vs ~173KB text. Negligible in the binary.

### Pattern 3: rbqn-gen binary with CBQN path

**What:** A Rust binary that reads CBQN gen/ C source files (same parser as current build.rs) and writes `.bin` files to `src/embedded/`. Also optionally verifies RBQN can compile the BQN sources.

```rust
// src/bin/rbqn_gen.rs — skeletal structure

fn main() {
    let cbqn_path = std::env::var("CBQN_PATH")
        .expect("CBQN_PATH required for rbqn-gen");
    let gen_dir = find_gen_dir(&cbqn_path)
        .expect("No gen/ dir found in CBQN_PATH. Build CBQN first.");

    // Step 1: Read CBQN gen/ files → ParsedComponent (same parser as old build.rs)
    let rt0 = parse_cbqn_gen(&read_file(gen_dir.join("runtime0")));
    let rt1x = parse_cbqn_gen(&read_file(gen_dir.join("runtime1x")));
    let cc = parse_cbqn_gen(&read_file(gen_dir.join("compiles")));
    let fmt = parse_cbqn_gen(&read_file(gen_dir.join("formatter")));

    // Step 2: Write .bin files to src/embedded/
    let embedded_dir = find_embedded_dir();
    write_bin(&embedded_dir.join("runtime0.bin"), &rt0);
    write_bin(&embedded_dir.join("runtime1x.bin"), &rt1x);
    write_bin(&embedded_dir.join("compiler.bin"), &cc);
    write_bin(&embedded_dir.join("formatter.bin"), &fmt);

    // Step 3 (optional): verify RBQN can compile BQN sources (SELF-01)
    if std::env::var("RBQN_VERIFY_SELF").is_ok() {
        verify_self_compilation(&cbqn_path);
    }

    println!("rbqn-gen: .bin files written to src/embedded/. Commit them.");
}
```

### Pattern 5: Excluding rbqn-gen from cargo install

**What:** `required-features` on a `[[bin]]` target means Cargo only builds it when that feature is enabled. `cargo install rbqn` uses default features (which don't include the feature), so rbqn-gen is not installed.

```toml
# Cargo.toml addition

[[bin]]

path = "src/bin/rbqn_gen.rs"

```

Developer usage: `CBQN_PATH=/path/to/cbqn cargo run --bin rbqn-gen --features gen-tools`

User usage: `cargo install rbqn` (only installs `rbqn` binary)

### Anti-Patterns to Avoid

- **Keeping the gen/ parser in build.rs alongside .bin support**: Creates two code paths. Move parser entirely to rbqn-gen.
- **Exact byte comparison for SELF-02**: Bytecode from RBQN's compiler may differ from CBQN's (constant folding, local variable ordering). Behavioral equivalence (run 13 tests) is the right check.
- **Making .bin files platform-specific**: Use little-endian throughout. BQN bytecodes are small integers; LE is fine on all targets.
- **Lazy/deferred decode of .bin files**: Decode all four .bin files in `bootstrap()` at startup. No lazy loading needed — they're small and always needed.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Binary format version detection | Custom version negotiation | Simple magic + version field checked at startup | One format forever; fail fast if wrong version |
| Test verification | Custom diff of bytecode arrays | Run existing `test_suite.sh` with new .bin files | 13 tests already defined, behavioral equivalence is sufficient |
| Cargo binary exclusion | Feature flag tricks | `required-features` on `[[bin]]` | Official Cargo mechanism, documented behavior |
| CBQN invocation in rbqn-gen | Shell subprocess to run CBQN binary | Read CBQN's pre-built gen/ files directly | CBQN must already be built; gen/ files are the artifact |

**Key insight:** The existing build.rs C-source parser is 250+ lines of correct code that handles all edge cases. Don't rewrite it — move it to rbqn-gen as-is.

## Common Pitfalls

### Pitfall 1: build.rs Cannot Use cargo:error Correctly in Stable

**What goes wrong:** Using `process::exit(1)` in build.rs to signal failure works but produces a poor error message. `cargo:error=` prints a nice message before the build fails.

**How to avoid:** Use `println!("cargo:error=...", ...)` then `process::exit(1)`, or use `panic!()` which Cargo formats better than a raw exit.

**Warning signs:** Error message says "build script failed" with no context.

### Pitfall 2: include_bytes! Path is Relative to Source File

**What goes wrong:** `include_bytes!("runtime0.bin")` in `src/embedded/mod.rs` resolves relative to `src/embedded/`, not to the crate root. This is correct if .bin files live in `src/embedded/`.

**How to avoid:** Place .bin files in `src/embedded/` alongside `mod.rs`. Don't use `OUT_DIR`-based paths — those only exist for build-script artifacts.

**Warning signs:** Compiler error "couldn't open file" or "no such file" during compilation.

### Pitfall 3: build.rs rerun-if-changed Not Set for .bin Files

**What goes wrong:** build.rs runs once; if .bin files change (rbqn-gen regenerated them), Cargo doesn't know to rebuild. include_bytes! will use stale embedded data.

**How to avoid:** Emit `cargo:rerun-if-changed=src/embedded/runtime0.bin` (etc.) from build.rs for each .bin file. Cargo then watches these files and rebuilds when they change.

**Warning signs:** After running rbqn-gen, cargo build doesn't pick up the new .bin content.

### Pitfall 4: OwnedBytecode Lifetime vs Bootstrap Interface

**What goes wrong:** `bootstrap.rs` currently calls `build_objs(&embedded::RUNTIME0, ...)` where `embedded::RUNTIME0` is a `&'static EmbeddedBytecode`. After switching to decoded `OwnedBytecode`, the decoded value must live long enough.

**How to avoid:** Decode all four at the START of `bootstrap()` into local `let` bindings. They live for the full duration of bootstrap. Pass `&OwnedBytecode` references down to `build_objs`, `exec_stage`, etc.

**Warning signs:** "does not live long enough" or "borrowed value does not live long enough" errors.

### Pitfall 5: c.bqn Needs •args for SELF-01 Compilation

**What goes wrong:** c.bqn line 1 is `func‿mod1‿mod2 ← •args`. Compiling it via `exec_string()` without setting `•args` causes a runtime error.

**Why it happens:** CBQN's cc.bqn wraps c.bqn by prepending the glyph literals, replacing `•args` effectively. RBQN's `exec_string` doesn't do this wrapping.

**How to avoid:** For SELF-01 verification in rbqn-gen, use the same wrapping that cc.bqn uses:
- Read c.bqn source text
- Replace the first line (`func‿mod1‿mod2 ← •args`) with the glyph literal assignment
- OR: set `•args` via `set_sys_args` before running exec_string (but set_sys_args takes `&[String]`, not BQN char arrays)
- Best approach: wrap c.bqn: `{func‿mod1‿mod2←𝕩 ⋄ [rest of c.bqn]}` and compile that block, then call it with glyph arrays.

**Warning signs:** "Error: domain error" or "rank error" on first line of c.bqn during rbqn-gen.

### Pitfall 6: rbqn-gen Must Find Its Own Executable for SELF-01

**What goes wrong:** To use RBQN's compiler for SELF-01, rbqn-gen needs to either (a) call the RBQN binary as a subprocess, or (b) call the same bootstrap + compile logic directly from within rbqn-gen.

**How to avoid:** Option (b) is cleaner — rbqn-gen is part of the rbqn crate and can call `bootstrap::bootstrap()` and `exec_string()` directly. This avoids subprocess management and is faster.

**Warning signs:** Circular binary invocation, path resolution issues.

### Pitfall 7: Bytecode Version Info for --version

**What goes wrong:** User wants `rbqn --version` to show bytecode source info ("CBQN-generated" vs "self-hosted"). The .bin files need to carry this metadata.

**How to avoid:** Embed a source tag string in the .bin file header: e.g., `source: [len: u16, bytes: [u8; len]]`. rbqn-gen writes "cbqn-2026-02-28" or "self-hosted-2026-02-28". At startup, read this string and store it. `--version` prints it.

### Binary encoder (in rbqn-gen)

```rust
fn write_bin(path: &Path, parsed: &ParsedComponent) {
    let mut buf = Vec::new();
    buf.extend_from_slice(b"RBQN");   // magic
    buf.extend_from_slice(&1u32.to_le_bytes()); // version

    // Source tag (for --version output)
    let tag = b"cbqn";
    buf.extend_from_slice(&(tag.len() as u16).to_le_bytes());
    buf.extend_from_slice(tag);

    // bc section
    buf.extend_from_slice(&(parsed.iarrs[parsed.bc_idx].len() as u32).to_le_bytes());
    for v in &parsed.iarrs[parsed.bc_idx] {
        buf.extend_from_slice(&v.to_le_bytes());
    }

    // iarrs section
    buf.extend_from_slice(&(parsed.iarrs.len() as u32).to_le_bytes());
    for arr in &parsed.iarrs {
        buf.extend_from_slice(&(arr.len() as u32).to_le_bytes());
        for v in arr { buf.extend_from_slice(&v.to_le_bytes()); }
    }

    // objs section (tag byte + payload)
    // ... (similar pattern)

    std::fs::write(path, &buf).expect("failed to write .bin");
}
```

### Binary decoder (in embedded/mod.rs)

```rust
pub fn decode_bytecode(bytes: &[u8]) -> OwnedBytecode {
    let mut cursor = Cursor::new(bytes);
    assert!(&bytes[..4] == b"RBQN", "invalid bytecode magic");
    let version = read_u32(&mut cursor);
    assert_eq!(version, 1, "unsupported bytecode version");

    // source tag
    let tag_len = read_u16(&mut cursor) as usize;
    let mut tag = vec![0u8; tag_len];
    cursor.read_exact(&mut tag).unwrap();

    // bc
    let bc_len = read_u32(&mut cursor) as usize;
    let bc: Vec<i32> = (0..bc_len).map(|_| read_i32(&mut cursor)).collect();

    // iarrs
    let iarrs_count = read_u32(&mut cursor) as usize;
    let iarrs: Vec<Vec<i32>> = (0..iarrs_count).map(|_| {
        let len = read_u32(&mut cursor) as usize;
        (0..len).map(|_| read_i32(&mut cursor)).collect()
    }).collect();

    // ... objs, blocks, bodies similarly

    OwnedBytecode { bc, iarrs, objs, blocks, bodies, source_tag: tag }
}
```

## Open Questions

1. **Should rbqn-gen also invoke CBQN to regenerate gen/ files, or only read existing ones?**
   - What we know: CBQN must be pre-built (gen/ files already exist) for rbqn-gen to work
   - What's unclear: whether rbqn-gen should run `make bytecodeLocal` itself
   - Recommendation: only READ existing gen/ files. Keep rbqn-gen simple. Document that CBQN must be built first.

2. **Should the initial committed .bin files be CBQN-generated or wait for SELF-01 verification?**
   - What we know: CBQN-generated is more reliable for bootstrapping; SELF-01 must verify parity
   - Recommendation: commit CBQN-generated .bin files first (enables SELF-04/05), then verify SELF-01/02, then optionally replace with RBQN-generated .bin files
   - The phase success criteria say "RBQN-compiled bytecode" for criterion 4 — so the FINAL committed .bin files should be RBQN-compiled

3. **How does rbqn-gen find the src/embedded/ directory?**
   - What we know: rbqn-gen is compiled into target/; it needs to write to the source tree
   - Recommendation: check `CARGO_MANIFEST_DIR` env var (set by Cargo when running with `cargo run`) OR accept an `--output` flag
