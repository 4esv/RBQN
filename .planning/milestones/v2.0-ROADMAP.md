# Milestone v2.0: CBQN Drop-in with GPU Acceleration

**Status:** ✅ SHIPPED 2026-03-03
**Phases:** 1–7
**Total Plans:** 33

## Overview

RBQN v2.0 delivers a standalone `rbqn` binary that is a 1:1 behavioral drop-in replacement for CBQN. Starting from a partially-broken VM with a failed runtime0 strategy, this milestone implemented Option B (native Rust primitive bypass), wired the full compiler pipeline, passed all 13 official BQN test files, integrated GPU acceleration for large arrays, achieved self-hosting (no CBQN build dependency), and finished with a zero-warning codebase with CBQN output parity.

**Timeline:** 2026-02-20 → 2026-03-03 (11 days)
**LOC:** ~127K lines Rust
**Commits:** 254

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Option B: bypass runtime0 overrides | 19 debug iterations failed; native Rust primitives already work | ✓ Correct |
| NaN-boxing (B = tagged u64) | Load-bearing architecture, too costly to change | ✓ Good |
| GPU via wgpu compute shaders | Cross-platform, no CUDA dependency | ✓ Good |
| f32 GPU with CPU f64 fallback | SHADER_F64 not universal on all GPUs | ✓ Good |
| Threshold-gated GPU dispatch | GPU overhead not worth it for small arrays | ✓ Good |
| Embed bytecode in binary | Eliminates CBQN build dependency for users | ✓ Good |
| 5-crate workspace structure | Separation of concerns (core/vm/prim/gpu/bin) | ✓ Good |

**Issues Resolved:**
- Fork monadic dispatch was computing wrong argument order
- SETH/PRED opcodes had broken body fallthrough
- compile_block produced wrong body pair ordering
- Namespace export (NSDesc) populated from wrong body_arr indices
- •Glyph returned wrong type (string) for primitive functions — should be char

**Issues Deferred:**
- SELF-02 human verification: self-compiled bytecode swap test not machine-recorded
- SYS-04 •state / SYS-15 •CurrentError: return SENTINEL (silent stubs)
- SYS-22 •FFI: throws NotImplemented on all calls
- •bit/•term/•ns namespaces: partial stubs
- GPU dispatch thresholds untested by official suite (too small arrays)

**Technical Debt Incurred:**
- Test scripts (test_suite.sh, test_cbqn_compat.sh) have hardcoded /Users/axel/ paths
- main.rs: -M heap_max flag parsed but ignored
- derive.rs: •math.Comb monadic always returns 1.0; •math.LCM monadic always returns 0.0
- REQUIREMENTS.md traceability: SIMP/PAR entries were stale (now archived)
