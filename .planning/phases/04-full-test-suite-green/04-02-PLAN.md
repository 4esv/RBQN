**Group (⊔) multi-dimensional — in group.rs:**

The monadic group `⊔x` where `x` is a list of index arrays (boxed array where each element is an integer array) is not implemented. Only single integer array is supported.

Add multi-dimensional group support:
1. In monadic group dispatch, check if `x` is a boxed array (each element is itself an array of integers). If so, use the multi-dimensional algorithm.
2. Multi-dim algorithm: `⊔⟨a,b,...⟩` groups by the index arrays a,b,... simultaneously. For each position i, the element belongs to group `(a[i], b[i], ...)`. The result is a nested array of shape `(max_a+2, max_b+2, ...)` where each cell contains elements at positions matching that multi-index.
3. For dyadic group `w⊔x` with list `w`: same approach but the shape/length is determined by the explicit `w` grouping.
4. Edge case: `⊔⟨⟩` should return `⟨⟩` (empty grouping).

This is complex. Implement the simplest correct version first. The BQN spec says: for `⊔l` where `l` is a list of lists, result has shape `1+⌈´¨l` and element at index `i` is `(i⊸=¨l)/¨⊸/↕≠⊑l`. Focus on making the test cases pass.

**Reshape (⥊) with ↑ auto-dimension — in structural.rs:**

In reshape_c2 (dyadic ⥊), check if any element in the shape array `w` is the ↑ function:
1. After converting `w` to a shape, check if any element is the ↑ function object. Compare using `prim_to_b(26)` (↑ is prim index 26 — verify this by checking dispatch.rs; it might be at index 11 for the ↑ slot).
2. Actually, the shape elements come from the BQN compiler. A shape like `↑‿3` means the compiler created a list `⟨↑, 3⟩` where ↑ is the function value. So check each element: if it's a function (not a number), it must be ↑, and compute the auto-dimension.
3. Auto-dimension formula: `auto_dim = ⌈(≠𝕩) ÷ (×´ other_dims)` — ceiling of element count divided by product of known dimensions.
4. Replace the ↑ entry with the computed dimension, then proceed with regular reshape.

NOTE: To identify the ↑ function, check if the shape element is a tagged function value (is_fun()) rather than a number. BQN only allows ↑ in reshape shapes, so any function in the shape position is ↑.
