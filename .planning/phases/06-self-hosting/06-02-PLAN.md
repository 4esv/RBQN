Add a `--verify` flag to rbqn-gen that tests RBQN's ability to compile BQN source files using its own compiler. This addresses SELF-01 (compile c.bqn) and SELF-02 (behavioral equivalence).

**Self-compilation approach:**
rbqn-gen is part of the rbqn crate, so it can call `bootstrap::bootstrap()` and `exec_string()` directly — no subprocess needed.

**Steps when --verify is passed:**

1. Bootstrap RBQN using the current .bin files (call `bootstrap::bootstrap()`).

2. Read BQN compiler source files from CBQN_PATH:
   - `src/c.bqn` — the compiler (~376 lines)
   - `src/r1.bqn` — runtime1
   - `src/r0.bqn` — runtime0
   - `src/f.bqn` — formatter

3. For c.bqn specifically: the first line is `func‿mod1‿mod2 ← •args`. This needs wrapping. Look at CBQN's `build/cc.bqn` for the glyph arrays it passes. The approach:
   - Read c.bqn source
   - Construct wrapped source: `{func‿mod1‿mod2←𝕩 ⋄ <rest of c.bqn>} ⟨funcGlyphs, mod1Glyphs, mod2Glyphs⟩`
   - The glyph arrays are: `funcGlyphs ← "+-×÷⋆√⌊⌈|¬∧∨<>≠=≤≥≡≢⊣⊢⥊∾≍⋈↑↓↕«»⌽⍉/⍋⍒⊏⊑⊐⊒∊⍷⊔!"`, `mod1Glyphs ← "˙˜˘¨⌜⁼´˝`"`, `mod2Glyphs ← "∘○⊸⟜⌾⊘◶⎉⚇⍟⎊"`
   - Use `exec_string()` to compile this wrapped source
   - If it succeeds without panicking, SELF-01 is satisfied

4. **Behavioral equivalence test (SELF-02):**
   - The real test is: can the RBQN-compiled bytecode run the 13 test files correctly?
   - After compiling the BQN sources, write them as .bin files (with source_tag "rbqn-self")
   - Then print instructions: "Self-compiled .bin files written. Run test suite to verify."
   - OR better: run `cargo test -p rbqn --test harness` as a subprocess to verify (if practical)
   - At minimum: compile c.bqn, runtime0, runtime1, formatter sources without crashing, and report success

5. Print results:
   - "SELF-01: c.bqn compiled OK (N bc instructions)"
   - "SELF-01: r0.bqn compiled OK"
   - "SELF-01: r1.bqn compiled OK"
   - "SELF-01: f.bqn compiled OK"
   - "SELF-02: Self-compiled .bin files written with tag 'rbqn-self'. Run test suite to verify behavioral equivalence."

**NOTE on complexity**: Compiling c.bqn is the hard test. The compiler source uses advanced BQN features. If RBQN can compile it without crashing, that's strong evidence of correctness. **If c.bqn compilation fails**: Wrap the compilation in `catch_unwind`. Print the error. Don't write self-compiled .bin files. Still exit 0 (verification is informational, not gating — the CBQN-generated .bin files are the shipping artifact).

**1. Expose source_tag from embedded module:**
Add a public function to `embedded/mod.rs`:
```rust
pub fn bytecode_source_tag() -> String {
    let bc = decode_bytecode(COMPILER_BIN);
    bc.source_tag
}
```
Or more efficiently, add a `decode_source_tag(bytes: &[u8]) -> String` that only reads the header (magic + version + source_tag) without decoding the full bytecode. This avoids decoding the entire compiler bytecode just for --version.

**2. Update --version in cli.rs:**
Change the `--version` handler from:
```rust
println!("rbqn {}", env!("CARGO_PKG_VERSION"));
```
to:
```rust
println!("rbqn {}", env!("CARGO_PKG_VERSION"));
println!("bytecode: {}", crate::embedded::bytecode_source_tag());
```

The source_tag will be "cbqn" for CBQN-generated bytecode (written by rbqn-gen Task 1 in plan 06-01) or "rbqn-self" for self-compiled bytecode.
