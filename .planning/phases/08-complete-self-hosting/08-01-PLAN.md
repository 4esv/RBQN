  <action>
    **Update `crates/rbqn/src/embedded/mod.rs`:**

    Change the four `include_bytes!` lines to reference the new `bins/` location. The path in `include_bytes!` is relative to the Rust source file, so use an absolute path via the `CARGO_MANIFEST_DIR` env + concat_bytes is not available — instead use `env!("CARGO_MANIFEST_DIR")` with `include_bytes!`. The correct pattern is:

    ```rust
    pub static RUNTIME0_BIN: &[u8] = include_bytes!(concat!(env!("CARGO_MANIFEST_DIR"), "/../../../bins/runtime0.bin"));
    pub static RUNTIME1_BIN: &[u8] = include_bytes!(concat!(env!("CARGO_MANIFEST_DIR"), "/../../../bins/runtime1x.bin"));
    pub static COMPILER_BIN: &[u8] = include_bytes!(concat!(env!("CARGO_MANIFEST_DIR"), "/../../../bins/compiler.bin"));
    pub static FORMATTER_BIN: &[u8] = include_bytes!(concat!(env!("CARGO_MANIFEST_DIR"), "/../../../bins/formatter.bin"));
    ```

    NOTE: `CARGO_MANIFEST_DIR` for the `rbqn` crate is `{repo_root}/crates/rbqn`. So `/../../../bins/` navigates to `{repo_root}/bins/`. Verify this resolves correctly with a test build.

    Also delete the old .bin files from `crates/rbqn/src/embedded/` (they are now in `bins/`):
    - Delete `crates/rbqn/src/embedded/runtime0.bin`
    - Delete `crates/rbqn/src/embedded/runtime1x.bin`
    - Delete `crates/rbqn/src/embedded/compiler.bin`
    - Delete `crates/rbqn/src/embedded/formatter.bin`
    - Keep `crates/rbqn/src/embedded/self-compiled/` directory (used by rbqn-gen --verify output)

    **Update `crates/rbqn/build.rs`:**

    Rewrite build.rs with these behaviors:

    1. **CBQN_PATH deprecation warning**: If `CBQN_PATH` env var is set, emit:
       `cargo:warning=CBQN_PATH is no longer needed — use `rbqn-gen --self` (with gen-tools feature) to regenerate bins`
       Do NOT fail. Do NOT use the value.

    2. **Locate bins/ directory**: Compute path as `{CARGO_MANIFEST_DIR}/../../..` + `/bins` (repo root).

    3. **Existence check**: For each of the four .bin files in `bins/`, if missing:
       ```
       panic!("Missing bins/{name}\nRun: cargo run -p rbqn --features gen-tools --bin rbqn-gen -- --self")
       ```

    4. **Rerun-if-changed**: Emit `cargo:rerun-if-changed=bins/{name}` for each file, and `cargo:rerun-if-env-changed=CBQN_PATH`.

    5. **Dev vs release logic** (per CONTEXT.md decisions):
       - In dev profile (`PROFILE != "release"`): also emit `cargo:rerun-if-changed=BQN_SRC` path if `BQN_SRC` env is set, so dev builds pick up BQN source changes.
       - In release profile: skip BQN_SRC rerun-if-changed entirely (always use committed bins).

    NOTE: The "dev profile recompiles if BQN source is newer" behavior is advisory metadata — actual recompilation of .bin files is done by the user running `rbqn-gen --self`, not by build.rs itself. build.rs only controls when Cargo re-runs the build script (via rerun-if-changed). This is the correct interpretation of the CONTEXT.md decision.
