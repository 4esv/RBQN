3. **`init(no_gpu: bool)`** — called from main.rs after CLI parse. If `no_gpu`, stores `None` in `GPU_RUNTIME` and sets `GPU_DISABLED`. Otherwise, attempts `pollster::block_on(GpuContext::new())`.    ```rust

   }
   pub fn log_dispatch(op: &str, len: usize, kind: &str) {

   - `pub fn arr_to_gpu_i32(gpu: &GpuRuntime, arr: &BqnArr) -> Option<GpuBuffer>` — converts I32 directly, I8/I16 by widening to i32, F64 by casting (caller must have verified gpu_safe_integer first). Returns None for unsupported types.
   - `pub fn gpu_i32_to_arr(gpu: &GpuRuntime, buf: &GpuBuffer, shape: Vec<usize>, fill: Option<B>) -> BqnArr` — downloads i32 data via `pollster::block_on(download_i32(...))`, creates `BqnArr` with `ArrData::I32` data and given shape/fill. Applies `squeeze_num` for compact storage.

8. **Threshold check** — `pub fn should_dispatch(op: &str, len: usize) -> bool` delegates to `rbqn_gpu::dispatch::should_use_gpu`.

  <action>
In `sort_i32` function in `crates/rbqn-gpu/src/kernels/sort.rs`:

Currently the function copies i32 bytes directly to a u32 buffer without sign-bit handling. Replace with:

1. Download the i32 data from `input` buffer.
2. Convert each i32 to sortable u32: `(v as u32) ^ 0x8000_0000u32` — this flips the sign bit, mapping i32 order to u32 order.
3. Upload the converted u32 data.
4. Call `radix_sort_u32` on the u32 buffer.
5. Download the sorted u32 result.
6. Convert back: `(v ^ 0x8000_0000u32) as i32` for each element.
7. Upload the corrected i32 data as the output buffer.

The function signature stays the same: `pub fn sort_i32(...) -> GpuBuffer`. The returned buffer should be `ElementKind::I32`.

NOTE: This is a CPU-side XOR pass (download, transform, upload). A GPU shader pass would be faster but is not necessary for Phase 5 — the sort kernel itself dominates for large arrays.
