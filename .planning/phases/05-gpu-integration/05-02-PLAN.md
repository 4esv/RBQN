```rust
use std::sync::OnceLock;

// NOTE: GPU dispatch hook — set by rbqn crate at startup via register_gpu_dispatch
type GpuArithFn = fn(op: &str, w_arr: &BqnArr, x_arr: &BqnArr) -> Option<BqnArr>;
static GPU_ARITH_HOOK: OnceLock<GpuArithFn> = OnceLock::new();
static GPU_ARITH_SCALAR_HOOK: OnceLock<fn(op: &str, scalar: f64, arr: &BqnArr, scalar_is_w: bool) -> Option<BqnArr>> = OnceLock::new();

pub fn register_gpu_arith(f: GpuArithFn) {
    let _ = GPU_ARITH_HOOK.set(f);
}
pub fn register_gpu_arith_scalar(f: fn(op: &str, scalar: f64, arr: &BqnArr, scalar_is_w: bool) -> Option<BqnArr>) {
    let _ = GPU_ARITH_SCALAR_HOOK.set(f);
}
```

**Map BQN op names to GPU kernel names.** Create a helper:

```rust
fn gpu_op_name(name: &str) -> Option<&'static str> {
```

**In `gpu_runtime.rs` (from plan 01), add the actual dispatch implementations:**

Add `pub fn gpu_arith_binary(op: &str, w_arr: &BqnArr, x_arr: &BqnArr) -> Option<BqnArr>`:
1. Check `get()` returns Some gpu runtime
2. Check `should_dispatch("arith", w_arr.ia())`
3. Check `gpu_safe_arr(w_arr) && gpu_safe_arr(x_arr)`
4. Upload both arrays via `arr_to_gpu_i32`
5. Create output buffer via `GpuBuffer::storage`
6. Call `rbqn_gpu::kernels::arith::arith_binary` with the GPU device, queue, cache
7. Download result via `gpu_i32_to_arr`
8. Log dispatch if debug enabled
9. Wrap entire body in `std::panic::catch_unwind` — if GPU errors, return `None` (CPU fallback) and log warning if debug enabled

Add `pub fn gpu_arith_scalar(op: &str, scalar: f64, arr: &BqnArr, scalar_is_w: bool) -> Option<BqnArr>`:
1. Similar checks as above but for single array
2. Upload array, use `rbqn_gpu::kernels::arith::arith_scalar` with `scalar as f32`
3. For `scalar_is_w=true`: op is `w op x` (e.g., `2×arr`). For `scalar_is_w=false`: need to handle `arr op scalar` — some ops are not commutative (sub, div). For sub: reverse by using `ScalarAdd(-scalar)` on negated result, or just call with swapped sense. Simplest: only dispatch scalar-array GPU for commutative ops (add, mul) or handle swap explicitly. Use `arith_scalar` which applies `arr[i] op scalar` — for `scalar_is_w=true` with non-commutative ops (sub, div), the scalar is on the left which `arith_scalar` doesn't handle. Best: only dispatch commutative ops (add, mul) for scalar path, or skip scalar GPU for now and let array-array handle it.
4. **Decision:** For Phase 5, only GPU-dispatch scalar-array when both elements are the same shape (i.e., both arrays). Skip scalar-array GPU dispatch for now — the threshold check on a single array still works but commutative handling is complex. Return None for all scalar-array calls to keep it simple. The array-array path is the primary win.

In `sort.rs`, add:

**In `grade_up_c1` and `grade_down_c1`**, add GPU dispatch before the CPU sort path:

For `grade_up_c1`:
```rust
if let Some(hook) = GPU_GRADE_HOOK.get() {
    if let Some(result) = hook(xa_arr, true) {
        return Ok(PrimResult::Array(result));
    }
}
```

For `grade_down_c1`:
```rust
if let Some(hook) = GPU_GRADE_HOOK.get() {
    if let Some(result) = hook(xa_arr, false) {
        return Ok(PrimResult::Array(result));
    }
}
```

The hook checks go AFTER the `xa_arr` extraction but BEFORE the CPU grade logic. Only intercept rank-1 arrays (sorting higher-rank or boxed arrays is CPU-only).

**In `gpu_runtime.rs`, add the grade dispatch:**

`pub fn gpu_grade(arr: &BqnArr, ascending: bool) -> Option<BqnArr>`:
1. Check `get()`, `should_dispatch("sort", arr.ia())`, `gpu_safe_arr(arr)`, `arr.rank() == 1`
2. Upload array via `arr_to_gpu_i32`
3. Call `rbqn_gpu::kernels::sort::sort_i32` (which now has the sign-bit fix)
4. The result is the sorted values, but BQN grade (⍋/⍒) returns **indices**, not sorted values. This means GPU sort alone doesn't directly give us grade. Two options:
   - (a) Sort pairs of (value, index) — requires a custom kernel or modifying radix sort
   - (b) Upload, GPU sort, download, then compute indices on CPU by matching
   - (c) Skip GPU grade for Phase 5 — the sort kernel sorts VALUES, not indices. Grade requires an argsort. The existing radix sort doesn't return permutation indices.

**Decision:** GPU grade (⍋/⍒) requires argsort, not sort. The existing `sort_i32`/`radix_sort_u32` only sorts values. Implementing GPU argsort requires either: (1) sorting key-value pairs where values are indices, which doubles memory and needs a new shader, or (2) a different algorithm. This is beyond the "wire existing kernels" scope of Phase 5.

**Revised approach:** Register the hook but always return `None` for grade — effectively CPU-only for now. Instead, wire GPU sort for **monadic sort (∧/∨)** on large numeric arrays if those functions exist. Check if sort_up_c1/sort_down_c1 exist in sort.rs — these sort VALUES (not indices) and CAN use the GPU sort kernel directly.

If sort_up_c1/sort_down_c1 exist:
```rust
type GpuSortFn = fn(arr: &BqnArr, ascending: bool) -> Option<BqnArr>;
static GPU_SORT_HOOK: OnceLock<GpuSortFn> = OnceLock::new();
pub fn register_gpu_sort(f: GpuSortFn) { let _ = GPU_SORT_HOOK.set(f); }
```

Hook into sort_up_c1/sort_down_c1 to GPU-sort rank-1 integer arrays. The GPU sort returns sorted values directly — perfect match.

`pub fn gpu_sort(arr: &BqnArr, ascending: bool) -> Option<BqnArr>`:
1. Check availability, threshold, safety, rank==1
2. Upload, call sort_i32 (ascending) or sort_i32 + reverse (descending)
3. Download result
4. For descending: reverse the downloaded i32 vec before creating BqnArr
5. Wrap in catch_unwind, log dispatch

**In `main.rs`, register:**
```rust
rbqn_prim::sort::register_gpu_sort(gpu_runtime::gpu_sort);
```
