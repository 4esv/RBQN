## Decided (and the one surprise)
- The lazy tree + fused host evaluator beats the GPU for elementwise/fold at
  every size ≤3e7 in a fresh process: W3 `a←↕1e7 ⋄ +´ 1+2×3+4×a` 9.9 ms
  host vs 16.7 forced GPU vs 30.9 before. Device init (8.3 ms, ~5.6 exposed)
  plus 0.7 ms per dispatch is the whole gap. So in default mode only sort
  ≥1.5M takes the GPU (W5 233→66 ms). `RBQN_GPU=force` keeps the full GPU
  path alive and correct (suite green under force).
- GPU fold is exact i64 up to 2^63 and rounds once; CPU and CBQN give an
  f64-chain result. `a←↕1e6 ⋄ +´ (a×a)+(a×a)`: GPU 666665666667000000
  (true), CPU 666665666668567000. Deviation accepted (basic parity).
- The earlier proof row `+\`↕1e7` never dispatched (sum >i32): use `⥊1`/`⥊3`
  inputs or i64 rows for GPU proofs.
- Worktrees spawned for agents start at stale local main 8232d63: always
  `git reset --hard perf/hot-path` first. The suite without `--diff`
  rewrites tracked `.test-results/baseline-latest*`.
- `pscs` now holds raw `*const Scope` handles (6cd2e8c) kept alive by the
  frame's own scope chain; review this if any scope-lifetime bug appears.
