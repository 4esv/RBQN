# GPU Optimized BQN in Rust: leads, 2026-10-09

Goal (Axel, 2026-10-09): BQN on the GPU, as fast as possible. CBQN is the
correctness yardstick (official test suite), not the design target.

Sources: upstream BQN f5706ec1..5abbab96 and CBQN f4257c14..b4db324a (fetched
as `upstream` in ~/Code/forks/{BQN,CBQN}); BQN implementation notes; ArrayFire,
CuPy, Futhark, Burn/CubeCL, linebender/vello docs; arXiv 2604.02344 (WebGPU
dispatch overhead); a per-row cost decomposition of every README bench row on
HEAD 958f2ed; and a dispatch microbenchmark run on this M3 Pro (wgpu 24, Metal).

## The measurement that decides the architecture

`scratchpad/dispatchbench`, 1M-element i32 `a+b`, 100 reps, 3 runs, ms/op:

| pattern | 1M | 10M |
|---|---:|---:|
| A: one submit per op + blocking readback per op (what rbqn does today) | 1.58-1.64 | 6.31 |
| B: one submit per op, data stays resident, one wait at end | 0.09-0.15 | 0.93 |
| C: all dispatches in one encoder, one submit, one wait | 0.06-0.10 | 0.89 |
| CPU add+sum, same data (fused, no output written) | 0.09 | 1.90 |
| device init (warm; cold first run was 215) | 9-15 | |
| first dispatch incl. WGSL compile | 1.7-3.6 | |
| upload 2x1M / download 1M | 3.6 / 1.6 | 20.5 / 6.8 |

Readback-per-op is the 1.5 ms "dispatch overhead" the thresholds in
dispatch.rs were tuned around. The actual dispatch floor is ~70-100 µs.
Resident at 10M the GPU is at memory bandwidth (~130 GB/s) and 2x the CPU.
Resident at 1M it ties the CPU on a single elementwise op and wins on any
chain. Today no bench row ever reaches the GPU (thresholds 10M-80M), and
end-to-end at the 10M scan threshold the GPU path costs 12 ms more than CPU,
of which ~12 ms is one-time init and compile (single vs triple scan: 39.3 vs
26.8, 74.7 vs 62.9).

## Ranked leads

1. **Device-resident array variant with lazy readback (L, the lever).**
   `ArrData::Gpu { buf: Arc<GpuBuffer>, host: OnceCell<..> }`, shape on the
   host so `≢`/`≠`/rank checks never sync. Readback only when a CPU primitive,
   print, or element access needs data; cache it. `Drop` frees via the pool.
   Count readbacks under RBQN_GPU_DEBUG so hidden syncs are visible. Models:
   Futhark C API opaque handles, ArrayFire/CuPy device arrays.
   Trap: scalar-returning ops (`+´`, comparisons feeding control flow) force a
   sync; return 1-element device values and read lazily.
2. **One open encoder, flush on sync point or cap (M, with 1).** Record every
   GPU primitive into a shared encoder; submit on readback, N pending ops, or
   X MB. Pattern C above. wgpu inserts hazards between dispatches. Trap:
   unbounded memory growth (Burn 0.18 and ArrayFire both document it); cap it.
3. **Pay init once, early (S).** Device init is 9-15 ms warm, 215 ms cold, and
   first-dispatch compile 2-4 ms per pipeline. Initialise on a background
   thread at startup and precompile the common pipelines; or persist a
   pipeline cache. Until then every single-op GPU use loses by ~12 ms.
4. **Lazy elementwise expression tree over device values (M).** Generalise
   fusion.rs from a syntactic chain to an AST per value (ArrayFire JIT, CuPy
   fuse); compile one WGSL kernel on materialisation, keyed by tree shape and
   dtypes, scalars as uniforms. Inline the map into reduce and scan loads.
   Materialise on non-elementwise consumer, fan-out >1, readback, or ~32 nodes.
5. **Subgroup ops in reduce and scan (S-M).** `Features::SUBGROUP` is probed
   in context.rs:62 but never requested, and no kernel uses
   `subgroupAdd`/`subgroupInclusiveAdd`. Read subgroup size from the adapter;
   do not hardcode 32. Modest win, memory-bound ops; do after 1-4.
6. **Keep scan as reduce-then-scan and sort as LSD radix (already so).**
   scan_i32.wgsl uses workgroup barriers only, sort.wgsl atomics only for the
   histogram. Metal gives no inter-workgroup forward progress (vello tests,
   Apple forums thread 831017, OOPSLA'21 arXiv 2109.06132), so decoupled
   look-back and Onesweep stay behind a feature flag if ever. Decoupled
   Fallback (b0nes164/GPUPrefixSums) is the Metal-safe single-pass option.
7. **Segmented reduce/scan for rank>1 folds (M, later).** `+˝` on a matrix
   as one segmented kernel, strategy picked by segment count vs size (Futhark).
8. **Thresholds (S, after 1-3).** Once resident and batched, lower per-op
   thresholds to the measured chain break-even (~1M elementwise, lower for
   chains), not 30M-80M.

## CPU floor (second priority, keeps mixed programs honest)

Per-row cost on HEAD, ms incl. 6.9 startup, with the specific gap:

| row | total | where it goes |
|---|---:|---|
| `+´↕1e7` | 16.6 | fold 5.8: scalar f64 dependent chain (typed.rs:36); CBQN i32→i64 SIMD chunks |
| `≠ ⊐ 3000000⥊↕1000` | 22.4 | reshape 14.7: boxed `get(i % n)` per element (structural.rs:436); ⊐ 0.8 |
| `+´⥊ (↕3000)×⌜↕3000` | 21.6 | table 4.6 checked i64 mul per elem (typed.rs:178); ⥊ 4.9 full clone (structural.rs:424) |
| `+´ +\` ↕5e6` | 20.2 | scan 9.5: f64 push + squeeze pre-pass (typed.rs:83) |
| `{𝕩+1}¨ ↕1e6` | 83.5 | ~77 ns/call: 2 mallocs (Rc<Scope> + vars Vec, scope.rs:21), ~6 id→fn hash lookups per call |
| fib 27 | 120.7 | ~180 ns/call, same path; `lt_c2` lacks scalar fast path |
| `≠ •Fmt ↕1e6` | 2959 | same f.bqn bytecode as CBQN; 1M tiny arrays each through `tag_arr` global HashMap (arrstore.rs:51), never freed |

Order if touching the CPU: typed reshape + zero-copy deshape (S, ~20 ms
certain) → block call path (M: single-allocation scope, cached fn pointer,
scalar fast path in `lt_c2`) → widening i64 sum and in-place i32→f64 scan (S)
→ table as row kernel with one up-front range check (M) → `•Fmt` native
fast path for rank-1 integer arrays, must match f.bqn byte for byte (S-M; the
real fix is the array registry, L). User lambdas (`¨`, recursion) cannot go
to the GPU; only pure elementwise-tree blocks under `¨` can route into lead 4
(Co-dfns and Dyalog-to-Futhark both restrict to first-order, non-recursive).

## Not worth it

Ryu/Dragonbox (floats only), AMX (undocumented), Swiss tables for ⊐ (already
dense table), Onesweep on Metal, whole-program fusion papers (Futhark,
Accelerate, Co-dfns) beyond the lazy-tree idea, CubeCL beyond a spike of its
runtime layer (tensor-shaped, fusion IR internal to Burn).

## Unverified

Apple subgroup size 32; wgpu Metal mapped buffers being zero-copy shared
storage; CubeCL runtime usable without Burn. Each is a measurement away.
